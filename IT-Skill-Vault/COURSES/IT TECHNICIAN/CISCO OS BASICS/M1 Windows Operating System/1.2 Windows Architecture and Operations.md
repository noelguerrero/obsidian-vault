
### Hardware Abstraction Layers
![[Pasted image 20261019101329.png]]

#### Upper Layer (User Mode) 

|**Component**|**Location**|**Purpose**|**Simple Example**|
|---|---|---|---|
|**Applications**|User Mode|Programs that users run. They cannot directly access hardware. They must ask Windows for services.|Chrome, Microsoft Word, Notepad, Games|
|**Windows API**|User Mode|The interface between applications and Windows. Applications call Windows API functions whenever they need Windows to do something.|A program calls `CreateFile()` to open a file or `MessageBox()` to display a pop-up.|
|**User-Mode Drivers**|User Mode|Drivers that don't require full system privileges. If one crashes, Windows usually keeps running because it's isolated from the kernel.|Printer drivers, USB device software, some camera drivers|

#### Middle Layer (Kernel Mode)

|**Component**|**Purpose**|**Simple Example**|
|---|---|---|
|**Operating System Kernel**|The core of Windows. It manages CPU scheduling, memory, processes, threads, and system resources. It decides which program runs and for how long.|Switching the CPU between Chrome and Spotify.|
|**Other Kernel-Mode Drivers**|Drivers that directly control hardware devices. They have unrestricted hardware access.|Graphics driver, network card driver, keyboard driver, mouse driver.|
|**File System Drivers**|Allow Windows to read and write different file systems. They translate file operations into disk operations.|NTFS driver reading a document from the SSD.|

#### Lower Layer

|**Component**|**Purpose**|**Simple Example**|
|---|---|---|
|**Hardware Abstraction Layer (HAL)**|Hides hardware differences from Windows. Instead of the kernel talking directly to every motherboard or CPU model, it communicates through the HAL. This makes Windows work on many different computers.|Whether your PC has an Intel or AMD CPU, the kernel uses the HAL instead of handling each CPU differently.|
|**Hardware**|The physical components of the computer.|CPU, RAM, SSD, GPU, keyboard, monitor, network card|

### User Mode and Kernel Mode
![[Pasted image 20261019102150.png]]

| **User Mode**                                                                          | **Kernel Mode**                                                                                  |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| • Runs installed applications (e.g., browsers, games, Office apps).                    | • Runs the operating system (Windows core).                                                      |
| • Has **no direct access** to hardware or physical memory.                             | • Has **unrestricted access** to all hardware and memory.                                        |
| • Must request the operating system to access hardware resources.                      | • Can directly communicate with hardware and execute any CPU instruction.                        |
| • Each application runs in its **own protected address space**.                        | • All kernel-mode code shares the **same address space**.                                        |
| • Applications are isolated from one another.                                          | • Kernel components are **not isolated** from each other.                                        |
| • If an application crashes, only that application is affected.                        | • If kernel-mode code crashes, the **entire operating system** may crash (Blue Screen of Death). |
| • Crashes are usually recoverable by restarting the application.                       | • Errors are often unrecoverable without restarting the computer.                                |
| • The kernel creates a separate process and protected memory for each application.     | • Can access and modify any memory location in the system.                                       |
| • Memory protection prevents applications from modifying the OS or other applications. | • A faulty driver can overwrite system memory and crash Windows.                                 |
| • Most Windows programs run in user mode.                                              | • Some device drivers run in kernel mode.                                                        |

#### Device Drivers

- Device drivers allow the **operating system** and **hardware devices** to communicate.
- Drivers can run in:
    - **User Mode** (safer; driver crashes usually affect only the driver or application).
    - **Kernel Mode** (faster but riskier; a faulty driver can crash the entire operating system).

### Windows File System

**exFAT**
- Simple file system supported by many different OS.
- FAT has limitation to the number of partitions, partition sizes, and file sizes that it can address.
- it is not usually used for HDD or SDD anymore.
- FAT16 and FAT32 are available to use, but FAT32 is the most common since it has fewer restrictions.


**Hierarchical File System Plus (HFS+)** 
- File system used on MAC OS X computers and allows much longer file names, file sizes, and partition sizes that previous file systems.
- it is not supported by windows without special software, but windows is able to read data from HFS+ partitions.


**Extended File System (EXT)**
- The file system used by Linux-based computers
- Also it is not supported by windows, but windows can read data from EXT partitions with special software.


**New Technology File System (NTFS)**
- Most common file system used in windows computer.
- All version of Windows and Linux support NTFS.
- Mac-OS X computers can only read an NTFS partition. They are able to write it with special drivers.


NTFS is the most widely used file system for windows and support vert large file and partitions and compatible with other OS.

**It also offer many security features such as data access control and MACE (make a timestamps of every activity on a file)**



**Before storage device such as disk can be used, it needs to be formatted with a file system.**

The devices needs to partition the hard drive, it divide into different areas called partitions, Each partitions is a logical storage that formatted to store information (data files or applications).

During the installation process most of the OS automatically partition and format the available drive space with a file system such as NTFS.

**NFTS formatting creates important structures for the disk storage, and tables for recording the locations of files: **

- **Partitions Boot Sector** - first 16 sectors on the drive. It contains the MFT, and the last 16 sectors it the copy or the backup of the boot sector.
- **Master File Table (MFT)** - This table contains the information of the files and directories on the partition, including file attributes such as security information and timestamps.
- **System Files** - These are hidden files that store information about volumes and file attributes.
- **File Area** - The main area of the partition where files and directories are stored.

**Noted:** Formatting partition, it is not mean that you completely removed and the previous file can recover. So it is recommended to perform security wipe on the drive to write all the data in the drive multiple times to ensure that there is no remaining data.

### Alternate Data Streams (ADSs)
- It is a feature of NTFS in windows that allows a file or folder to contain one stream of data.

NTFS also allows files to have ADSs, which are additional hidden data streams attached to the same file.  These are used by applications to store extra information without creating another file.

In cybersecurity, ADSs are important because they can used to hide a malicious code inside of it, and another file can later access and execute that code.

In NTFS, an **Alternate Data Stream (ADS)** is attached to a file by adding a colon (`:`) followed by the stream name, such as `Testfile.txt:ADS`.

Syntax:  `fileName:adsName` Example: `Textfile.txt:ADS`

![[Pasted image 20261021192825.png]]

In this example, the command stores the text **"Alternate Data Here"** inside the ADS instead of the main file. 

When you use the normal `dir` command, only `Testfile.txt` is shown and it appears to have **0 bytes** because the data is stored in the hidden ADS. 

You can read the hidden data using `more < Testfile.txt:ADS`, and the `dir /r` command displays the ADS attached to the file.

### Windows Boot Process
It is a sequence of steps that Windows follows to start the computer.

![[Pasted image 20261021193943.png]]

**Windows Boot Process**

|Step|Description|
|---|---|
|**1. BIOS Initialization / UEFI Initialization**|When you press the power button, the computer starts the firmware. Older computers use **BIOS**, while modern computers use **UEFI**. Both initialize the hardware and begin the boot process.|
|**2. MBR (BIOS only)**|If the computer uses BIOS, it reads the **Master Boot Record (MBR)** from the hard drive. The MBR contains the code needed to locate the Windows Boot Manager.|
|**3. EFI Files (UEFI only)**|If the computer uses UEFI, it reads the **EFI System Partition (ESP)** and loads the Windows boot files (`bootmgfw.efi`).|
|**4. POST (Power-On Self-Test)**|The firmware checks that the hardware (CPU, RAM, keyboard, storage, etc.) is working properly before Windows starts.|
|**5. Bootmgr.exe (Windows Boot Manager)**|The Windows Boot Manager starts and reads the boot configuration to determine how Windows should boot.|
|**6. BCD (Boot Configuration Data)**|The **BCD** is a database containing the Windows boot settings, such as which operating system to load and any startup options.|
|**7. Hibernation Check**|Windows checks whether the computer was placed into **hibernation** instead of being shut down normally.|
|**8a. Winresume.exe** _(if hibernated)_|If Windows was hibernated, **Winresume.exe** restores the previous session instead of performing a normal boot.|
|**8b. Winload.exe** _(normal boot)_|If Windows was shut down normally, **Winload.exe** loads the Windows kernel, drivers, and essential system files into memory.|
|**9. KMCS (Kernel Mode Code Signing)**|Verifies that important kernel-mode drivers are digitally signed and trusted before they are loaded.|
|**10. Ntoskrnl.exe**|The **Windows Kernel** is loaded. It manages memory, processes, hardware communication, and other core operating system functions.|
|**11. HAL (Hardware Abstraction Layer)**|HAL acts as a bridge between Windows and the computer's hardware, allowing Windows to work with different hardware without major changes.|
|**12. SMSS (Session Manager Subsystem)**|Starts the Windows user session, creates system processes, and prepares the operating system for user logon.|
|**13. Hiberfil.sys** _(hibernation only)_|The file where Windows saves the contents of RAM during hibernation. It is read by **Winresume.exe** to restore the previous session.|
|**14. Logon**|Windows displays the login screen. After you sign in, your desktop and applications are loaded.|


**Two types of computer firmware:**

1. **Basic Input-Output System (BIOS)**
- created early 1980s
- It is a firmware stored on a chip on the computer's motherboard.
- It is the first software that runs when you turn on the computer.
- Its jo is to check if the hardware is working properly, find a bootable device (such as SDD or HDD), and start the operating system

2. **Unified Extensible Firmware Interface (UEFI)**
- It is a modern replacement for BIOS
- It is faster, more secure, and supports newer hardware features

### Windows Startup

**Two registry items that are used to automatically start applications and services**
- **HKEY_LOCAL_MACHINE** - Several aspects of windows configuration are stored in this key, including about services that start with each boot.
- **HKEY_CURRENT_USER** - Several aspects related to the logged user are stored in this key, including information about services that start only when the user logs on to the computer.

Note: **Windows Registry** is a **hierarchical database** that stores the configuration settings and options for the Windows operating system, hardware, installed applications, and user preferences.

Different entries in these registry locations define which services and applications will start, as indicated by their entry type. These types include Run, RunOnce, RunServices, RunServicesOnce, and Userinit.

These entries can be manually entered into the registry, but it is much safer to use the **Msconfig.exe** tool. This tool is used to view and change all of the start-up options for the computer. Use the search box to find and open the Msconfig tool.

**5 Tabs of msconfig**
**1. General** - contains different start up types such as, 
- Normal that loads all drivers and services.
- Diagnostic loads only basic drivers and services.
- Selective allows the user to choose what to load on start up.
  
**2. Boot** - Any installed OS can be chosen here to start. There are also an option for safe boot for troubleshoot start up.
   
**3. Services** - All installed services are listed here so that they can be chosen to start at startup.

**4. Startup** - All application and services that are configured to automatically begin at start up can be enable or disabled by opening task manager.

**5. Tools** - Many common operating system tools can be launched directly from this tab.

### Windows Shutdown

It is best to shutdown properly the computer, because it close the running services first so the applications didn't damaged.

During shutdown the computer will close the following.
1. User Mode Applications 
2. Kernel Mode Processes

Note:
- if the user mode process does not respond with a certain amount of time, the OS will display a notification and allow the user to wait for the respond, or forcibly end the processes.
- If a kernel mode process does not respond, the shutdown will hang, and it may be necessary to shutdown the computer with power button.


- **Shutdown -** Turns the computer off (power off).
- **Restart -** Re-boots the computer (power off and power on).
- **Sleep** - Saves the current state of the computer in RAM only, and to keep the state, it needs a electricity.
- **Hibernate -** Saves the current state of the computer to RAM to HDD or SDD, then it fully shutdown the computer. (it doesn't need electricity).

### Memory Allocation and Handles

When the program is running, Windows first loads its instructions and data into RAM. The CPU then reads these instructions from RAM and executes them.

However, programs doesn't access RAM directly, instead, Windows gives every process a **virtual address space.**

And the address that program use called **virtual addresses**, and Windows translates these virtual address into actual physical addresses in RAM using page table. 

This allow windows to manage memory efficiently and prevents program from interfering with each other.

- On a **32-bit Windows** system, each process can use up to **4 GB** of virtual address space. 
- On a **64-bit Windows** system, each process can use up to **8 TB** of virtual address space, allowing much larger applications.

Process running in user mode has its own private memory space, so other user space cannot changes another process's memory.

If process needs to use operating system resources (kernel resources), it must requires access through a process handle. 

The process handle acts like a permission ticket that lets the process safely communicate with the windows kernel instead of accessing it directly.

**Five Hives of the Windows Registry**

| Root Key                       | Purpose                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| **HKEY_LOCAL_MACHINE (HKLM)**  | Stores settings for the entire computer, such as hardware, drivers, and installed software.       |
| **HKEY_CURRENT_USER (HKCU)**   | Stores settings for the currently logged-in user, such as desktop background and personalization. |
| **HKEY_CLASSES_ROOT (HKCR)**   | Stores file associations and information about file types and COM objects.                        |
| **HKEY_USERS (HKU)**           | Stores settings for all user accounts on the computer.                                            |
| **HKEY_CURRENT_CONFIG (HKCC)** | Stores information about the current hardware configuration being used.                           |

Note:
- Hives cannot create. Only registry keys and values in the hives can create, modified, or deleted by administrator account.
