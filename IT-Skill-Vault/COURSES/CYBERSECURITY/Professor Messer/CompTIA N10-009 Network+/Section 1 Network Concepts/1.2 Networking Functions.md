## Content Delivery Network (CDN)
It’s a system of distributed servers located around the world that work together to deliver web content (like images, videos, scripts, and web pages) to users more quickly and efficiently.

**How it works**
Instead of loading a website from a single server (which might be far away), a CDN:
- Stores copies of content on multiple servers (called _edge servers_)
- Sends data to users from the **nearest server** to their location

**If a website is hosted in the US but you’re in India:**
- Without a CDN → data travels from the US (slower)
- With a CDN → data comes from a nearby server in India (faster)

## Virtual Private Network (VPN)
is a tool that makes your internet connection more **private and secure**.

**When you use a VPN:**
- Your data is **encrypted**
- Your **IP address is hidden**
- Your internet traffic goes through a **VPN server first** before reaching websites

**Concentrator (Head-end)**
is basically the **main device that manages all VPN connections in a network**.

**How it works (flow)**
1. You connect to the VPN using your client
2. Your request goes to the **concentrator (head-end)**
3. It verifies your identity
4. It sets up a **secure tunnel** (encrypt and decrypt the data)
5. Your data passes through that tunnel to the internal network

## Time To Live (TTL)
is a mechanism that limits the lifespan or "period of validity" of data in a computer or network. Think of it as an expiration date or a self-destruct timer that prevents data from circulating indefinitely or becoming stale.

**How it Works**
1. A TTL value is assigned when the data is created or sent.
2. The value is **decremented**:
    - By **1 per hop** (in networking), or
    - By **time countdown** (in caching systems)
3. When the TTL reaches **0**:
    - The data is **invalidated, dropped, or removed**
4. A TTL value is assigned when the data is created or sent.

## Routing Loops
- Another example of Time To Live (TTL)
- is when a packet gets stuck going in circles between routers instead of reaching its destination.

**Why it’s an example of TTL:**  
Because this is exactly the situation TTL is meant to fix.
- Without TTL → the packet would loop forever
- With TTL → each hop reduces the TTL
- When TTL hits 0 → the packet is **stopped (dropped)**

**Loops could cause a packet to live forever**
- Solution: Drop the packet after a certain number of hops

**Each pass through a router is a hop**
- Default TTL for macOS/Linux 64 hops
- Default TTL for Windows is 128 hops
- When the hops reach 0 it drops the packet

**In the Routers the TTL is associated with the number of hops.**

### However the DNS the TTL is associated with the total number of seconds 


**How it works (simple flow)**
1. You request a domain (e.g., a website)
2. A DNS resolver finds the IP address and **stores it in cache**
3. The record comes with a TTL value (e.g., 300 seconds)
4. The resolver starts a **countdown from 300 → 0**

- While TTL > 0 → it **reuses the cached result** (fast, no new lookup)
- When TTL = 0 → cache is **expired**, so it **asks the DNS server again**
