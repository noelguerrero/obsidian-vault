## Network Function Virtualization (NFV)
- is a technology that turns traditional network hardware devices into **software that runs on virtual machines or servers**.
- It replace physical network device into virtual devices
	- like: Router, Switch, load balancer, firewalls, etc.
	- It manage using hypervisor
- Quick and easy to deploy network functions.
	- Like replacing new firewalls, router and other devices.
- Many different deployment options
	- Virtual machine, container, fault tolerance, etc.

Common application inside the cloud infrastructure is **Virtual Private Cloud (VPC).**

## Connecting To The Cloud

![[Pasted image 20260508210929.png]]

- **Virtual Private Cloud (VPC)**
	- It is a private network inside a cloud provide like Amazon, Google Cloud, Azure.
	- Might include: web server, database server, load balancer, routers, etc - All of that runs inside the VPC
- Common to create many VPCs in large environment
	- They would have separe VPC for different application.
	- This allow you to keep all this system separated but still allow you to manage all of them as virtual appliances. 
- Transit gateway (It connects the VPCs together)
	- is like a **central router or network hub** that connects multiple networks together.
- VPC uses VPN 
	- to be able gain a secure connection between customer router and VPCs
- VPC use internet gateway or Virtual Private Cloud Gateway
	- is a component in a VPC that allows resources inside the VPC to communicate with the internet.
- VPC also use NAT gateway
	- It allows **private servers inside the VPC to access the internet** while still remaining **private and protected from incoming internet connections**.
- VPC Endpoint
	- It allows resources inside your VPC to connect to cloud providers like AWS services **privately without using the public internet**. (it creates direct connection between VPC and cloud providers)

## Security Groups And Lists
Many cloud providers will include additional security that you can layer on top of your VPCs. like:

**Firewall for the cloud**
![[Pasted image 20260508215131.png]]
- Control inbound and outbound traffic flows
- Layer 4 (port number) You can define a TCP or UDP port number and add that to our inbound and outbound rules
- Layer 3 (address) 
		- We can allow packets coming from specific addresses or an entire block of addresses using CIDR block notation 
		- Or specify IPv4 or IPv6 ranges directly within your security group.

## Network Security List
In your cloud providers front-end you would include in your network security list, is the list of rules that you would like to assign

![[Pasted image 20260508220026.png]]

- Assign a security rule to an entire IP subnet
	- It applies to all device in the subnet.
- Once you define your network security list it applies to all VPCs
	- It becomes difficult to manage
	- Not all devices in a subnet have the same security posture
	- The rules need to be very specific because broad rules may not provide the right level of security.

**There is a way to be specific in terms of rule called Network Security list** 

****
## Network Security Group
is a security feature used in cloud platforms (especially **Microsoft Azure**) to control network traffic. It is more flexible than NSL

![[Pasted image 20260508221212.png]]
- It assign a security rule to a specific virtual NIC (VNIC)
	- **VNIC:** it is the **virtual version of a physical network card** used by virtual machines or cloud instances.
	- You can now applies to specific devices and network connections.
- Better control and granularity (specific)

### Difference of NSG and NSL

| Feature        | NSG (Network Security Group)      | Network Security List (NSL)         |
| -------------- | --------------------------------- | ----------------------------------- |
| Cloud Provider | Microsoft Azure                   | Oracle Cloud Infrastructure         |
| Applied To     | Subnet or Network Interface (NIC) | Subnet only                         |
| Granularity    | More detailed control             | Less detailed control               |
| Reusable       | Yes                               | Usually tied to subnet              |
| Rule Scope     | Can protect individual VMs        | Protects all resources in subnet    |
| Stateful       | Yes                               | Yes                                 |
| Flexibility    | High                              | Lower                               |
| Example Use    | Different rules per VM            | Same rules for all subnet resources |

**If you ifnd that you need additional security above this, you make look on virtual firewall or other virtualize platform to include additional security.**
