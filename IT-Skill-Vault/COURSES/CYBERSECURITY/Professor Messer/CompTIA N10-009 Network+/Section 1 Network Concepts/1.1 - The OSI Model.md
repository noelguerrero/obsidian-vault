**What is the OSI model?**
- Open Systems Interconnection Reference Model
- it is a guide of how data traverse in the system.

**Key word to remember each layer of OSI model:**
All People Seem To Need Data Processing.

****
## Layer 1 - Physical Layer
- The layer that sends the actual signals through cables or air.

**The physics of the network**
- Signaling, cabling, connectors
- It describe the physical signal that send into cables and other connectors on our network.

**You have a physical layer problem**
- fix your cabling, punch-downs, etc.
- Run loop tests, test/replace cables, swap adapter cards.

**Purpose:** Sends raw bits physically.

**What it does:**
- Transmits electrical/light/radio signals
- Handles cables/hardware

**Examples:**
- Ethernet cables
- Wi-Fi signals
- Fiber optics

**Real-life Example:**  
Actual wire (fiber, cables) that carrying the signal.

****
## Layer 2 - Data Link Layer
- The layer that sends data between devices on the same network.

**The basic network "language"**
- the foundation of communication at the data link layer

**Data Link Control (DLC) protocols**
- MAC (Media Access Control) address on Ethernet

**We often refer this layer to switching layer.**
![[Pasted image 20260409232851.png]]

when someone talk about MAC address they referring the hardware address of that particular adapter card.

**Purpose:** Transfers data between devices on same network.

**What it does:**
- Uses MAC addresses
- Frames data
- Detects errors in local network

**Examples:**
- Ethernet
- Switches operate here

**Real-life Example:**  
- Helps data move from your PC to your router.
- Internet frame, MAC address, Extended Unique Identifier (EUI-48, EUI-64), Switch and so on.

****
## Layer 3 - Network Layer
- The layer that chooses where data should go.

**The "routing" layer**
- This is the layer that router use to determine how to forward traffic.
- They specifically looking at the destination IP
- this is the layer that Fragments frames to traverse different networks

**Purpose:** Determines the best path or where should data go.

**What it does:**
- Routing
- Logical addressing

**Examples:**
- IP Addressing
- Routers work here

**Real-life Example:**  
- Like GPS finding the route to destination.
- IP Address, Router, Packet


****
## Layer 4 - Transport Layer
- The layer that makes sure data is delivered correctly.

**Purpose:** Ensures proper delivery of data.

**What it does:**
- Breaks data into segments
- Error checking
- Flow control
- Reliable/Unreliable delivery

**Protocols:**
- TCP (Transmission Control Protocol)
- UDP (User Datagram Protocol)

**Real-life Example:**  
- Makes sure your downloaded file arrives complete.
- TCP segment, UDP datagram

****
## Layer 5 - Session Layer

- The layer that starts, keeps, and ends communication between devices.
- Provides communication management between devices (start, stop , restart).
- Control protocols, tunneling protocols

**Purpose:** Manages communication sessions.

**What it does:**
- Opens connections
- Maintains sessions
- Closes sessions

**Examples:**
- Login sessions
- Video call connection management

**Real-life Example:**  
- Keeps your Zoom/Discord call active.
- Control protocols, tunneling protocols


****
## Layer 6 - Presentation Layer

- The layer that changes data into a format that devices can understand.
- Character encoding
- Application encryption
- Often combined with the Application Layer

**Purpose:** Formats or translate the data so both devices understand it.

**What it does:**
- Data translation
- Encryption / Decryption
- Compression

**Examples:**
- SSL/TLS encryption
- JPEG, PNG, MP4 formatting

**Real-life Example:**  
- Makes sure encrypted website data can be read properly.
- Application encryption (SSL/TLS)

****
## Layer 7 - Application Layer

- The layer where users interact with network applications.
- Common application that operates at OSI layer 7: HTTP, FTP, DNS, POP3
- It’s **not the app itself**, but the **network services that allow the app to communicate over the network**.


**Purpose:** Interface between the user/application and the network.


**What it does:**

- Lets software communicate with the network
- Provides network services to applications
- Where users interact with the network through apps.

**Examples:**

- HTTP / HTTPS (web browsing)
- FTP (file transfer)
- SMTP (email)

**Real-life Example:**  
When you open Chrome and visit Google.
